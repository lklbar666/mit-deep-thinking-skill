# 三个自造案例（完整四步）

三个案例都是为演示结构而构造的，不是书中案例，也不是真实公司数据。
数字仅用于说明关系，不作事实引用。

## 案例一：B2B SaaS 续费率连续三个季度下滑

### 现象与初判

续费率从 92% 降到 84%。团队第一反应：加客户成功人手、多做培训、给折扣续约。
执行一轮后，续费率回到 87%，两个季度后又跌到 83%。

### ① 建模

| 角色 | 内容 |
|---|---|
| 输入源 | 实施人力、客户培训投入、产品迭代速度 |
| 输出点 | 客户业务部门（不是采购部门） |
| 竞争者 | 竞品低价方案；客户「自研小工具」；「干脆不用」 |
| 合作者 | 客户的 IT 实施方、行业顾问 |
| 影响者 | 客户公司的预算周期与组织调整 |

层次：表层是「续费动作」，中层是「客户用得多深」，深层是「客户内部谁在为这套系统说话」。

因果（只留因果）：
`用得多 → 业务部门依赖 → 采购时有内部支持 → 续费`（正）
`只做培训不做流程改造 → 用得不深 → 依赖弱`（负）
`折扣续约 → 采购部满意、业务部无感 → 下一年更易流失`（负，延迟一期）

### ② 动力机制

- 模式：**衰减**，且被折扣掩盖成「振荡」（好一期、差一期）
- 存量：客户内部的使用深度与「内部支持者数量」——都是靠时间积累的存量
- 流量：本期的培训场次、折扣力度——只能短期拉动
- 作用与反作用：给折扣 → 采购部形成「等降价」预期 → 越到后期越难按原价续
- 三回合推演：折扣续约 → 次年原价谈判失败 → 再折扣 → 客户认定价格可谈 → 毛利持续下滑

### ③ 支点

诊断：问题不在「客户成功人手不够」，在于**输出点选错了**——一直对采购部交付，而使用深度由业务部决定。

支点：把交付对象从采购部改为业务部的具体岗位，并给每个客户培养至少两个「内部支持者」。
这是给存量（内部支持者数量）加输入，不是加大流量（培训场次）。

### ④ 行动与验证

- 最小动作：选 8 家客户，各做一次业务流程改造（不是培训），产出一份「改造前后工时对比」
- 观察 6 周：主指标=业务部周活跃岗位数；防副作用=实施人力占用
- 判据：6 周内活跃岗位数上升 ≥20% → 支持；仅培训满意度上升而活跃不变 → 支点选错

## 案例二：社区团购的团长大量流失

### 现象与初判

三个月内团长流失 40%。运营的判断：佣金太低，加佣金。加了两个点，流失放缓一个月，又恢复。

### ① 建模

| 角色 | 内容 |
|---|---|
| 输入源 | 货源稳定性、佣金比例、平台提供的工具与素材 |
| 输出点 | 小区居民（团长是渠道，不是客户） |
| 竞争者 | 其他平台在同一个小区挖团长；团长自己进货 |
| 合作者 | 物业、小区便利店 |
| 影响者 | 平台补贴政策、监管对自提点的要求 |

层次：表层是「佣金」，中层是「团长在小区里的信任资产」，深层是「平台是否把团长当可替换的流量位」。

因果：
`货源不稳 → 团长在邻居面前失信 → 信任资产下降 → 团长退出`（负）
`佣金提高 → 短期留人 → 平台补贴收缩 → 佣金回落 → 更快流失`（负，延迟一期）

### ② 动力机制

- 模式：**衰减**，且被补贴做成锯齿
- 存量：团长在小区里的**信任资产**（推荐一次坏货就掉一截，攒回来很慢）
- 流量：佣金、补贴、活动
- 本源动力：货源稳定性——它决定信任资产的净变化
- 相变点：当小区里出现第二个平台且货源更稳时，团长的切换成本骤降，整批人会一次性走掉

### ③ 支点

诊断：佣金是流量，信任资产是存量。加佣金不改存量方向。

支点：把「货源稳定性」做成对团长可见的承诺——缺货提前告知、坏货包退、按周公示履约率。
这等于给存量加正向输入，同时把平台从「可替换的流量位」改成「共担风险的合作方」。

### ④ 行动与验证

- 最小动作：在 3 个小区试点「履约率周公示 + 坏货当日退」
- 观察 8 周：主指标=团长 8 周留存率；防副作用=单均履约成本
- 判据：留存率高于对照组 10 个点 → 支持；只有满意度上升而留存不变 → 支点无效

## 案例三：个人「每天加班但产出没增加」

### 现象与初判

每天工作 11 小时，交付量三个月没变。初判：效率低，要学时间管理。
用了番茄钟、待办清单，两周后放弃。

### ① 建模

| 角色 | 内容 |
|---|---|
| 输入源 | 时间、注意力、睡眠 |
| 输出点 | 可交付的成果（不是「完成的任务条数」） |
| 竞争者 | 临时插入的会议与请求；同岗位其他人的优先级 |
| 合作者 | 能挡事的同事、能授权的下属 |
| 影响者 | 上级对「响应速度」的隐含期待 |

层次：表层是「时间分配」，中层是「任务选择」，深层是「用响应速度换取安全感的激励结构」。

因果：
`响应快 → 被派更多临时任务 → 深度工作时间被切碎 → 交付质量下降 → 需要更多时间补救 → 更晚下班`（正反馈，越转越紧）
`睡眠少 → 注意力差 → 同样工作更久`（负）

### ② 动力机制

- 模式：**增长型正反馈**，但增长的是「被派活的量」，不是产出
- 存量：注意力与信誉。注意力每天清零，信誉靠交付积累
- 流量：当天的工作时长
- 作用与反作用：你响应得越快，别人越把你当默认通道——这是反作用，且有延迟（几周后才显形）
- 拐点：当「响应速度」的边际收益低于「交付质量」的边际收益时，策略该切换

### ③ 支点

诊断：加班是流量手段，真正的问题是**信誉的来源被定成了响应速度，而不是交付质量**。

支点：把「响应」改成有节奏的批量响应（每天两个固定时段），并把「本周交付了什么」变成对外可见的记录。
这改的是激励结构里的信号，不是时间管理技巧。

### ④ 行动与验证

- 最小动作：连续两周，只在 10:00 和 16:00 处理临时请求，其余时间关通知
- 观察 4 周：主指标=每周完成的可交付成果数；防副作用=被投诉次数、上级评价
- 判据：成果数上升且投诉未显著增加 → 支持；投诉激增 → 说明前提（上级确实要求即时响应）成立，需先改前提再改动作

**这个案例的关键**：如果第 4 步发现「即时响应」是硬性前提，那么支点不在自己身上，
而在「向上管理这个前提」——这正是「原因不在结果旁边」的应用。
