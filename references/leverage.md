# 支点手册：用最小改动撬动结构

## 一、为什么不能直接压现象

现象是结果。压结果，结构不动，反作用会更强：

- 销量跌 → 加大促销 → 提前透支需求 → 下期跌得更狠
- 员工没干劲 → 加考核 → 只做被考核的事 → 整体效率更低
- 吵架 → 道歉 → 积压的不满没减 → 下次吵得更凶

**规则**：先确认要动的是模型里的哪个节点，再谈具体动作。

## 二、五种找法

### 1. 查前提

任何方案都建立在若干前提上。前提塌了，方案再精致也没意义。

问法：

- 这个方案默认哪件事不会变？
- 那件事现在还是这样吗？
- 如果它变了，方案还剩什么？

典型：整个行业都在优化「订货批量」，但真正的机会是取消「必须保库存」这个前提。

### 2. 原因不在结果旁边

原因可能在上一个环节、上一个部门、上一任负责人、上一个时代。

问法：

- 出问题的地方，是不是只是「最后承压」的地方？
- 往上追两环，谁把压力传过来的？
- 如果换掉这一环的人，问题会消失吗？

### 3. 扩大范围

把可能受影响的所有角色列全，直到「思考范围 = 影响范围」。

问法：

- 这个决定会让谁的日子变好／变差？
- 谁有否决权？
- 谁的沉默其实是反对？

漏掉一个关键角色，方案会在执行阶段莫名卡住。

### 4. 抬高视角

先确认「这是不是真问题」，再谈怎么解。

问法：

- 这是老板的问题、客户的问题，还是我自己的问题？
- 解完之后，谁的处境真的变好了？
- 如果这个问题永远不解，会怎样？

很多努力花在解一个本不该解的问题上——解对了也没人受益。

### 5. 先定判据

动手前写下三件事：

- 看到什么算成功（可观察，不是「感觉好多了」）
- 多久看结果
- 什么情况下承认失败并停止

**没有判据的方案，一定会被延长解释为「还在见效中」。**

## 三、四类支点形态

| 形态 | 做法 | 适用 |
|---|---|---|
| 加泄流阀 | 给存量开一个定期释放的出口 | 积压型问题（不满、技术债、疲劳） |
| 插刹车 | 在正反馈里加限制，牺牲速度换稳定 | 扩张失速、烧钱换增长 |
| 引入强制约束 | 用机制替代自觉 | 存钱、健身、复盘这类靠意志力的事 |
| 换掉前提 | 不优化现有公式，而是让公式失效 | 行业惯例明显不合理时 |

**共同点**：支点通常落在**存量**上，或落在**能改变前提的那个角色**上。
落在流量上的动作（加预算、加人、加活动）多数是治标。

## 四、验证设计

支点选好后，不要一次上全套：

1. 选一个最小可验证动作（一周内能做完、能观察到结果）
2. 指定观察指标（一个主指标 + 一个防副作用指标）
3. 设定时间窗与判据
4. 结果回来，先判断错在哪一层：
   - 动作没做到 → 执行问题，重做
   - 动作做到了但结构没动 → 支点选错，回第二步
   - 结构动了但结果没变 → 模型错，回第一步
   - 短期好了长期更差 → 只动了流量，误判为支点

## 五、常见错判

| 症状 | 真实原因 |
|---|---|
| 方案有效但只能维持三个月 | 动的是流量，存量没变 |
| 越推越费劲 | 撞上了别人的反作用，且反作用有延迟 |
| 各部门都达标，整体没改善 | 指标切分错了，局部最优≠整体最优 |
| 换了三任负责人都一样 | 问题在结构，不在人 |
